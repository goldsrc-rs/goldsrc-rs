# GoldSrc.rs — Modern Rust Framework for GoldSrc Modding

[![CI](https://github.com/ulquiorracode/GoldSrc.rs/actions/workflows/ci.yml/badge.svg)](https://github.com/ulquiorracode/GoldSrc.rs/actions/workflows/ci.yml)

**GoldSrc.rs** is a modern framework written in Rust for creating plugins and server-side
modifications for the GoldSrc engine (Half-Life 1, Counter-Strike 1.6, and other GoldSrc-based games).

The project aims to fully replace the outdated C++ / AMX Mod X / Pawn stack, providing memory-safe
operation (Safe Rust), WebAssembly (WASM) plugin sandboxing, true hot-reloading, and a modern
developer experience.

## Philosophy

1. **Dependency Inversion:** A unified `goldsrc-api` trait interface that runs on top of the legacy
   C++ Metamod (compatibility mode) or as a standalone proxy GameDLL (Standalone mode).
2. **Zero Reverse Engineering:** No guessing memory offsets. We leverage community knowledge
   (ReHLDS, Metamod-r, Orpheu, HamSandwich) and automate FFI generation via `rust-bindgen`.
3. **Safety First:** Plugins are sandboxed inside a WASM runtime (`wasmtime`). A crashing plugin
   cannot segfault the server — it is isolated and can be hot-reloaded without a restart.

## Architecture (Workspace)

| Crate | Purpose |
| --- | --- |
| `goldsrc-sys` | Raw `unsafe` FFI bindings generated by `bindgen` from HLSDK and Metamod headers. |
| `goldsrc-api` | Pure Rust traits and safe handle types (`Engine`, `Plugin`, `Entity`, `Player`). |
| `goldsrc-metamod` | Backend: `.dll`/`.so` plugin for Metamod-r (compatible with Reunion, WHBlocker, etc.). |
| `goldsrc-standalone` | Backend: proxy GameDLL loaded directly by HLDS via `liblist.gam` (no Metamod needed). |
| `goldsrc-wasm-host` | Embedded Wasmtime JIT engine for loading and hot-reloading WASM plugins. |
| `goldsrc-macros` | Procedural macros: `#[plugin]`, `#[command]`, `#[on_load]`. |
| `goldsrc` | Public SDK for plugin authors: ECS, Event Bus, config watchers, logging macros. |

## Branching Strategy

- `main` — stable releases only (protected, requires PR + 1 approval).
- `dev` — active development (protected, requires PR + 1 approval).
- `feature/<name>` — feature branches from `dev`, merged back via squash PR, deleted after merge.
