# План исправлений GoldSrc.rs (все находки аудита → «идеальный вариант»)

Приоритеты: **P0** = критично (краш сервера / неработающее центральное обещание), **P1** = архитектурный долг (совпадает с целью v0.9.0 из ROADMAP), **P2** = DX и качество API, **P3** = полировка. Оценка размера: S (<1 ч), M (несколько часов), L (день+).

## P0 — Критические исправления

**P0.1. Вернуть panic-изоляцию в release — S**
- `Cargo.toml` (корень): убрать `panic = "abort"` из `[profile.release]` (lto/strip/opt-level оставить).
- Причина: с abort хелпер `catch_ffi_panic` (catch_unwind) не работает физически — любой panic в release убивает весь HLDS, что противоречит цели v0.9.0 «no Rust panic can crash HLDS».
- Проверка: принудительный panic в хуке под release-сборкой → сервер печатает ошибку и живёт.

**P0.2. Соединить мост WASM↔Engine (убрать mock-хост-функции) — L**
- В `goldsrc-api`: узкий объектно-безопасный трейт `EngineOps: Send + Sync` (или переиспользовать существующий `Engine`).
- `HostState` (`backends/goldsrc-wasm-host/src/manager.rs:50-128`): принять `Arc<dyn EngineOps>` через `PluginManager`; все `host_entity_*`/`host_player_*`/сеттеры делегируют движку вместо констант (`true`/`100.0`/`"Player"`).
- Оба бэкенда передают свой `Engine`-импл при `HostRuntime::init` — трейт `Engine` наконец становится load-bearing (DIP начинает реально работать).
- Убрать `"(mock)"` из `Entity::print_chat`/`Player::print_chat`; нативный `Auth::has_capability` связать с `CapabilityRegistry`.
- Результат: WASM-плагины впервые получают доступ к реальному игровому состоянию (в рамках текущей WIT-поверхности; расширение до 140+ функций остаётся в v0.10.0).

**P0.3. Починить консоль standalone-бэкенда — S**
- Задрейнить `PRINT_QUEUE` в конце `hook_start_frame` (после `forward_start_frame`); убрать `#[allow(dead_code)]` с `hook_start_frame_post` (`lib.rs:185-207`).
- Использовать общий с metamod код экранирования `%`/`{`/`}` — иначе вернётся краш ReHLDS fmtlib.
- Лечит: бесконтрольный рост очереди + полную потерю консольного вывода в standalone-режиме.

**P0.4. Soundness: aliasing UB и дыры в panic-guard — M**
- `wasm_manager()` в обоих бэкендах чеканит свежий `&'static mut PluginManager` из `static mut` при каждом вызове → заменить на безопасный синглтон (`SyncWrapper` / `Mutex` с токеном), исключив пересекающиеся `&mut`.
- metamod `hooks.rs`: `hook_client_command`/`hook_start_frame` перевести на общий `catch_ffi_panic` вместо самописного catch_unwind; добавить guard в `hook_client_connect`.

## P1 — Архитектурный долг (цель v0.9.0)

**P1.1. Общий слой для бэкендов (дедупликация ~150+ строк) — M**
- Новый крейт `goldsrc-backend-common` (или модуль в `framework/goldsrc` за фичей `host`): импл `Engine`, параметризованный источником engfuncs; макросы `call_engfunc!`; `PrintQueue` на `VecDeque` с полным `drain` + экранирование + обрезка; CLI-регистрация.
- Бэкенды становятся тонкими адаптерами (это буквально пункт «Core Refactoring» из v0.9.0).
- Заодно лечит: drain по одному сообщению за кадр через `Vec::remove(0)` (O(n)) в metamod.

**P1.2. Честный жизненный цикл плагинов — M**
- WIT: добавить `on-unload` в `world goldsrc-plugin`; вызывать при unload/reload; `PluginInfo.has_on_unload` — по linker export checks, не хардкод `false`.
- `is_poisoned`: ставить `true` при трапе `call_*`, логировать один раз, прекратить вызывать упавший плагин каждый кадр.
- Watcher: debounce ~150 мс (компилятор пишет файл в несколько проходов).
- Config watcher: обрабатывать `.toml`-события в `on_server_frame` → `on_event("config_changed", path)` (сейчас события получают и молча выбрасывают).

**P1.3. Единая таксономия ошибок — M**
- `thiserror`-енумы: `wasm-host` (`LoadError`/`HostError`), `framework` (`InitError`/`CommandError`); заменить `Result<String, String>` и `Box<dyn Error>`.
- RwLock-poison unwrap'ы внутри host-функций (`manager.rs:92-121`) → восстановление с логом вместо паники.

**P1.4. CI и воспроизводимость — S**
- `cargo test --workspace` (host-таргет) в ci.yml; закоммитить `Cargo.lock` (убрать из .gitignore — workspace производит бинарники); опционально `cargo audit`.

## P2 — DX и качество API

**P2.1. Proc-макросы: диагностика и корректность — M**
- `syn::Error` со спанами на: неизвестные атрибуты `#[plugin]`, неверные сигнатуры хендлеров, маркеры `#[on_load]` без `#[plugin]` (сейчас — молчаливые no-op).
- Экранировать `"` и `\` в генерируемом TOML-метаданных (сейчас невалидный TOML при кавычке в имени).
- Поддержать `dependencies = ["name@>=1.0"]` — десериализатор на хосте уже готов (`plugin.rs:33-59`), пример `vip_menu` уже его использует.

**P2.2. События и команды: из broadcast в реестр — M**
- Payload событий: минимум индекс игрока в `client_connect`/`client_disconnect` (плагин сейчас не может узнать, кто подключился).
- Команды: `HashMap<name, plugin_idx>` вместо линейного перебора всех плагинов; consume-семантика через `call_on_command -> bool` (поле «reserved for future» уже есть).
- Мёртвые типы `events.rs` — либо задействовать, либо удалить.

**P2.3. Гигиена слоёв — M**
- Убрать `pub use goldsrc_sys` из SDK-фейса `framework/goldsrc` (или спрятать за фичей `unsafe-sys`); убрать `*mut edict_t` из публичных сигнатур `goldsrc-api` (opaque handle, конверсия только внутри бэкендов).
- Схлопнуть ~20 пар `#[cfg(wasm32)]`/`#[cfg(not(...))]` в `Entity`/`Player` общим кодом/макросом.
- WIT-файл: заменить path-coupling (`../../core/goldsrc-api/wit/...`) на нормальную зависимость (общий крейт-источник).

**P2.4. Логгер — S**
- Держать файл открытым (сейчас open/close на каждую строку под мьютексом на потоке движка); категории Core/Proxy/Wasm/Plugin + секция `[logging]` в goldsrc.toml — как заявлено в v0.9.0.
